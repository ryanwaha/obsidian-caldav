# M4 編輯 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.

**Goal:** 在 Obsidian 裡修改任務或事件的狀態、標題、日期。寫入伺服器時以原始 ICS 為底，只改插件負責管理的欄位；收到 412 時，伺服器上沒有衝突的修改就自動合併後重送，真正的衝突才讓使用者選；離線的修改先進待送佇列。

**Spec:** `~/docs/homelab/obsidian-caldav.md`
- §4.3：只做輕量編輯；重複 VTODO 不能改狀態；重複 VEVENT 不能編輯
- §4.4：寫入時保留原有內容，只修補插件管理的屬性
- §5.2 E2／E3
- §7.2：編輯介面、衝突處理、待送佇列

## 範圍與規則

| 物件 | 可編輯欄位 |
|---|---|
| 不重複的 VTODO | 標題、狀態（完成／未完成）、到期日 |
| 重複的 VTODO | 標題、到期日（等於移動整個系列，和 iOS 的模型一致）；**不能改狀態**（§4.3） |
| 不重複的 VEVENT | 標題、開始時間（結束時間跟著平移，長度不變） |
| 重複的 VEVENT，或帶有 override（`hasOverrides`）的物件 | 不能編輯（§4.3） |
| 刪除、查無此物、有歧義、待送新建 | 不能編輯 |

### 修補規則（`applyPatch`）
- **只動被修改的欄位**，其他全部原樣保留：未知欄位、`X-APPLE-*`、VALARM、CATEGORIES 等都不碰（§4.4，T1）。
- **完成**：寫 `STATUS:COMPLETED`、`COMPLETED:<UTC>`、`PERCENT-COMPLETE:100`。
- **取消完成**：寫 `STATUS:NEEDS-ACTION`，並移除 COMPLETED 和 PERCENT-COMPLETE。
- **日期**（E3）：
  - 只有日期時寫 `VALUE=DATE`。
  - 有時間時寫 `TZID=Asia/Taipei`；行事曆裡還沒有這個 VTIMEZONE 就補上。
  - 不寫 UTC，也不寫 floating。
- **改 VTODO 的 DUE**：
  - 如果原本的 DTSTART 等於原本的 DUE（iOS 的寫法），DTSTART 跟著改成同一個值。
  - 絕對時間的 VALARM（`TRIGGER;VALUE=DATE-TIME`）平移同樣的時間差；帶 `X-APPLE-PROXIMITY` 的位置提醒不動。
- **改 VEVENT 的 DTSTART**：DTEND 平移同樣的時間差；絕對時間的 VALARM 也一樣平移。
- **每次修補都要**：
  - 更新 `DTSTAMP` 和 `LAST-MODIFIED`（UTC）；
  - VEVENT 若已經有 `SEQUENCE`，加 1。

### 寫入與衝突
- **連線時**：PUT `If-Match: <etag>`。
  - etag 是空的（M3 留下的情況）：先 GET 一次，取得目前的 etag 再寫。
  - 收到 412：GET 目前的版本。這次修改涉及的每個欄位，如果伺服器上的值都還等於修改前的值，就把修改套到伺服器版本上，帶新的 etag 重送一次。
  - 有任何一個欄位伺服器也改過：標記為衝突，交給使用者選「用我的」或「用伺服器的」。
- **離線或暫時性錯誤**：放進待送佇列，作為一筆 update 操作，每個物件最多一筆，後來的修改合併進去。快取先寫入修改後的版本（樂觀更新），flush 時照上面的規則送出。
- 同步時，清單的變更用伺服器版本覆蓋快取；待送的 update 在每輪同步一開始的 flush 就會送出。

## Tasks

1. **`src/ical/patch.ts`**：
   - `Patch = { summary?: string; done?: boolean; date?: { date: string; time?: string } | null }`
   - `applyPatch(ics, patch, now): string`
   - `managedValues(ics): { summary, done, date }`：衝突比對用。
   - 以 fixtures 測試：
     - T1 的未知欄位都保留；
     - 位置提醒保留，而且不平移；
     - 絕對時間的 VALARM 平移；
     - DTSTART 跟著 DUE 改；
     - 完成和取消完成的欄位正確；
     - VEVENT 的結束時間平移；
     - 補 VTIMEZONE；
     - 原本是全天，改成全天；
     - 原本是 UTC，改成 TZID；
     - 摺行不超過 75 octets；
     - SEQUENCE 加 1。
2. **`src/ical/editable.ts`**：`editable(obj): { title: boolean; done: boolean; date: boolean }`，依上面的表格。用表格驅動測試。
3. **`CalDavClient.get(href)`**：回傳 `{ status, ics, etag }`；401 時丟例外。
4. **待送 update**：
   - `PendingCreate` 改名為 `PendingOp`，加上 `op: "create" | "update"`。舊資料沒有 `op` 欄位，視為 create。
   - update 帶的欄位：`baseIcs`、`baseEtag`、`patch`，以及 `conflict?: { server: managed values; serverIcs; serverEtag }`。
   - `state` 新增 `"conflict"`。
   - 同一個 href 有多筆 update 時合併 patch。
   - 引擎 flush update 的規則：
     - 2xx：寫進快取，移出佇列。
     - 412：GET 後自動合併並重送，或標為衝突。
     - 404：標為失敗，原因是「伺服器上已刪除」。
     - 其他錯誤比照 create。
   - 測試要涵蓋上述所有分支。
5. **插件 UI**：
   - `DetailModal` 依 `editable()` 顯示可以修改的欄位，加上「儲存」按鈕。
   - 衝突時並列兩邊的值，提供「用我的」或「用伺服器的」兩個選擇。
   - chip 上任務的圖示（☐／☑）可以直接點擊切換完成；不可編輯時，點了就照舊開詳情。
   - `editObject(obj, patch)` 的流程：
     1. 寫入待送 update
     2. 樂觀更新快取
     3. 重載索引
     4. 執行 `syncNow("編輯")`
   - 狀態欄列出衝突的項目。
6. **headless 驗證與發佈 0.4.0**：
   - 用 curl 建立暫存物件，在 Obsidian 修改標題和日期，再完成它；GET 回來確認未知欄位保留。
   - 在 Obsidian 修改的同時，用 curl 改另一個欄位：要自動合併。
   - 改同一個欄位：要出現衝突，選了之後的結果要正確。
   - 透過轉送埠模擬離線修改，連線後要送出。
   - 驗證完清理所有暫存資料。

## Review Focus

1. 修補後原始 ICS 裡的其他內容都要保留，包括 iOS 的 VALARM 位置提醒、`X-APPLE-*` 和 CATEGORIES。
2. 412 時的自動合併不能吃掉伺服器上別人做的修改。
3. 重複任務的狀態、重複事件，在 UI 上不能改，資料層也要擋下來。
4. 離線修改之後，伺服器上同一筆又被改了：連線後要正確合併或標為衝突，不能直接覆蓋。
5. 點 chip 的勾選框要切換完成，不能又打開詳情，也不能誤觸發其他動作。
