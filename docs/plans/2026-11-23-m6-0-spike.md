# M6-0 實測（spike）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 回答設計文件 §11 的 S1–S6，每一項得到「通過／不通過＋證據」，不通過的套用 §11 寫好的退路，讓 M6-1 之後的計畫建立在實測事實上。

**Architecture:** 不寫產品程式碼。S4、S6 用 curl 與 CDP `page.evaluate` 直接驗證；S1、S2、S3 用一個丟棄式探針插件（只記錄事件、附加一個測試 widget）在獨立的 spike 實例與臨時 vault 裡，以 CDP 真實點擊與輸入驗證；S5 用兩個臨時 vault 接一個**專用的** CouchDB 資料庫模擬兩台裝置。所有結果逐項寫進結果紀錄檔，最後回填設計文件。

**Tech Stack:** **獨立的 spike Obsidian 實例**（同一個 1.13.7 執行檔，Xvfb `:98`、`--user-data-dir ~/m6-spike/userdata`、`--remote-debugging-port=9223`，與正式實例完全分離），以 `playwright-core` 的 `chromium.connectOverCDP('http://127.0.0.1:9223')` 操作：`page.evaluate` 取代 `obsidian eval`，`page.mouse`／`page.keyboard` 做真實的點擊與輸入，`page.screenshot` 留證據（2026-11-23 已驗證可連線、可截圖）、Radicale 3.9.2、CouchDB + Self-hosted LiveSync 0.25.56、TypeScript + esbuild（探針插件）。

**Spec:** `docs/plans/2026-11-23-m6-server-projection-design.md`（§11 的 S1–S6 與各自的退路）

## Global Constraints

- **不得碰 CouchDB 的 `markdowns` 資料庫**，也不得在任何 vault 執行 LiveSync 的 rebuild 類操作，除非該 vault 接的是本計畫建立的 `m6-spike` 資料庫（見 `services/obsidian-server.md`、incident 2026-09-12）。
- **不得修改正式 vault**（`/ssd-pool/obsidian/obsidian`）與其 `.obsidian/`。
- Radicale 只動 `/ryanw/test/` 和本計畫建立的 `/ryanw/m6-spike/`；`test` 裡使用者既有的物件（例如 test2）不動。暫存物件 UID 一律以 `m6-spike-` 開頭，結束時刪除。
- 所有 GUI 操作都在 spike 實例上做，**不碰正式實例**（不重啟 `obsidian.service`、不改 `~/.config/obsidian/`）。啟動：
  `xvfb-run --server-num=98 --server-args="-screen 0 1600x1000x24" /opt/Obsidian/obsidian --user-data-dir=$HOME/m6-spike/userdata --remote-debugging-port=9223 --disable-gpu --password-store=basic`
  CDP 只綁 127.0.0.1。驅動腳本與 `playwright-core@1.49.1` 放 `spike/m6-probe/driver/`。
- 臨時 vault 放在 `~/m6-spike/vault-a`、`vault-b`；結束時 `rm -rf ~/m6-spike`。
- 帳密只從 `~/.config/radicale/password.txt`、`~/docker/couchdb/.env` 讀進環境變數，不寫進 repo、不寫進結果紀錄。
- 探針程式碼放 `spike/m6-probe/`，只在 `m6` 分支上，M6-1 合併前刪除。
- 每項結果記錄：Obsidian 版本、測試日期、指令與原始輸出（節錄）、結論（通過／不通過）、套用的退路。
- GUI 操作一律由 agent 透過 CDP 執行並截圖為證。只有標 👤 的步驟（iPhone 與 Windows 上的確認）需要使用者，先給清單、等回覆。
- 已知限制：Chromium 的原生 date picker 彈窗不在 DOM 裡，點不到；日期改用在 input 裡輸入值，並在結果裡註明與手動點選的差異。

## Review Focus

spike 只在 headless 桌面版（1.13.7）上測，下列情況測不到，但使用者日常會遇到。結果紀錄裡每一項都要寫明「已測／未測，風險」：

1. **iOS Obsidian（1.15.1）的 Live Preview**：widget 位置、點擊範圍是否和桌面一致 → Task 4 結束時列一份 iPhone 手動檢查清單給使用者（👤）。
2. **版本差異**：headless 1.13.7 與 iOS 1.15.1、Windows 版本不同，Bases 的可編輯性可能不同 → Task 6 記錄各結論適用的版本。
3. **LiveSync 合併設定因裝置而異**：S5 的結果取決於各裝置的合併設定 → Task 7 記錄測試時的設定值，並列出 iPhone、Windows 目前的值（👤 讓使用者截圖或讀出）。
4. **datetime 屬性的時區**：Properties 的 datetime 寫入格式（有沒有時區、秒數）→ Task 6 記錄原始 frontmatter 文字。
5. **中文與特殊字元標題當 alias**：`[[` 自動完成插入時有沒有跳脫或截斷 → Task 5 用含 `：`、`|`、`#` 的標題各測一次。
